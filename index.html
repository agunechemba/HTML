Introduction

Why HTML Still Matters

The language of the web — small, semantic, and everywhere

HTML — Hypertext Markup Language — is the language in which the web is written. It is not a programming language; it has no logic, no loops, no conditions. It is a markup language: a way of describing what content is, so that browsers, search engines, screen readers, and other tools can make sense of it.

This book is compiled from Stack Overflow Documentation — the collective knowledge of thousands of web developers who have wrestled with HTML and written down what they learned. It is not a tutorial. It is a reference, a set of professional notes for people who already build for the web and want to build it better.

The book has seven parts. Part One covers the foundations: getting started, doctypes, headings, paragraphs, text formatting, and anchors. Part Two moves through lists, tables, comments, classes, data attributes, and linking external resources. Part Three covers JavaScript inclusion, CSS, images, image maps, input controls, and forms. Part Four is about structure: divs, sectioning elements, navigation, labels, output elements, and void elements. Part Five handles embedded content: media, progress bars, selection menus, embeds, iframes, and content languages. Part Six covers SVG, canvas, metadata, and marking up code and quotes. Part Seven closes with tabindex, global attributes, the HTML5 cache, event attributes, character entities, and ARIA.

HTML is deceptively simple: a handful of tags, a few attributes, and you are done. But the deeper you go, the more you realise how much of accessibility, performance, and maintainability depends on getting the semantics right. This book is about getting the semantics right.

Every chapter follows the same shape: a short story drawn from the source, a representative code example, a box of Key Ideas, and three Try It Yourself exercises. Wherever you start, welcome.

  • The book is compiled from Stack Overflow documentation — a professional reference, not a tutorial.

Getting started with HTML

Markup, not programming — the language of the web

HTML — Hypertext Markup Language — uses a markup system composed of elements that represent specific content. Markup declares what is presented, not how; visual styling is the job of CSS. HTML is sometimes called a programming language, but it has no logic — it is a markup language whose tags give semantic meaning and machine-readability to content.

An element usually consists of an opening tag <element_name>, a closing tag </element_name>, and the content between them. Void elements — <img>, <meta>, <link>, <input> — have no closing tag and no content. Element names are descriptive keywords: video, audio, table, footer.

A page may contain hundreds of elements which a browser reads, interprets, and renders into human-readable or audible content. HTML files can be written in any text editor and must be saved with a .html or .htm extension.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Hello!</title>
  </head>
  <body>
    <h1>Hello World!</h1>
    <p>This is a simple paragraph.</p>
  </body>
</html>

Break the example down: <!DOCTYPE html> defines the HTML version; <html lang="en"> opens the page and declares its language; <head> holds metadata that never appears in the browser window; <meta charset="UTF-8"> declares the character encoding; <title> sets the tab or window title; and <body> contains all visible or audible content.

Key Ideas

  • HTML is a markup language, not a programming language — it has no logic.
  • Elements have an opening tag, content, and a closing tag — except void elements.
  • <!DOCTYPE html> must be the very first line.
  • <head> holds metadata; <body> holds visible content.
  • Modern pages should declare <meta charset="UTF-8">.

Try It Yourself

  1. Create a file called hello.html and open it in a browser.
  2. Add a second paragraph and reload the page.
  3. Remove the <!DOCTYPE html> line and observe any differences.

DocTypes

One line at the top that tells the browser what to expect

Doctypes — short for "document type" — help browsers understand the version of HTML the document is written in for better interpretability. Doctype declarations are not HTML tags and belong at the very top of a document, before the <html> tag.

HTML5 is not based on SGML, so it does not require a reference to a DTD. The HTML5 doctype is simply <!DOCTYPE html>. That single line tells the browser to render the page in standards mode rather than quirks mode.

The string DOCTYPE is ASCII case-insensitive, so <!doctype html> and <!DOCTYPE HTML> are also valid — but the conventional form is all-uppercase DOCTYPE.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Document</title>
  </head>
  <body></body>
</html>

Key Ideas

  • The doctype goes at the very top of the document, before <html>.
  • HTML5 does not need a DTD reference — one line is enough.
  • <!DOCTYPE html> is case-insensitive, but uppercase is conventional.
  • The doctype triggers standards mode in browsers.

Try It Yourself

  1. Remove the doctype from a page and observe how rendering changes.
  2. Try <!doctype html> in lowercase — it still works.
  3. Compare your page in standards mode versus quirks mode.

Headings

Six levels of hierarchy — and why getting them right matters

HTML provides six separate header tags to indicate headings of various sizes and thicknesses: <h1> through <h6>. <h1> is the largest and most important; <h6> the smallest and least important. Every heading tag supports all global attributes.

Search engines and other user agents index page content based on heading elements — for example, to build a table of contents. So using the correct structure matters. In general, an article should have one <h1> for the main title, followed by <h2> subtitles, going down a layer only when necessary.

Headings should describe the content they precede — not be used merely to make text large. If you want big text, use CSS. If you want a heading, use a heading tag, because assistive technologies and search engines rely on the structure.

<h1>Main title</h1>
<p>Introduction</p>

<h2>Reasons</h2>
<h3>Reason 1</h3>
<p>Paragraph</p>
<h3>Reason 2</h3>
<p>Paragraph</p>

<h2>In conclusion</h2>
<p>Paragraph</p>

Key Ideas

  • Six heading levels, <h1> to <h6>, in decreasing importance.
  • One <h1> per page is the usual convention.
  • Heading structure affects SEO and assistive technology.
  • Do not use headings merely to make text big — use CSS for styling.

Try It Yourself

  1. Write a document with one h1, two h2s, and a few h3s. View the source in a browser's accessibility inspector.
  2. Try removing the h1 and observe how the structure looks to a screen reader.
  3. Rewrite a page you have written so that the heading hierarchy is a valid outline.

Paragraphs

The most basic HTML element, and how whitespace actually works

The <p> element defines a paragraph. The <br> element inserts a single line break, and <pre> defines pre-formatted text where whitespace and newlines are preserved.

You cannot be sure how HTML will be displayed. Large or small screens, and resized windows, will create different results. With HTML, you cannot change the output by adding extra spaces or extra lines in your source — the browser collapses any run of whitespace into a single space when rendering.

That collapsing behaviour is important: if you want precise whitespace, use <pre> or CSS. If you want a visual line break without starting a new paragraph, use <br> sparingly — it has no semantic meaning and is generally discouraged for layout.

<p>This is a paragraph.</p>
<p>This is another paragraph.</p>

<p>First line.<br>
Second line.</p>

<pre>This text
preserves    spacing
and line breaks.</pre>

Key Ideas

  • <p> is the basic paragraph element.
  • Whitespace in the source collapses into a single space when rendered.
  • <br> inserts a line break; use it sparingly.
  • <pre> preserves whitespace and newlines.
  • Styling is the job of CSS — use elements for structure, not appearance.

Try It Yourself

  1. Write two paragraphs separated by several blank lines in the source — observe the output.
  2. Use <br> to split a single paragraph across three lines.
  3. Compare the output of <p> and <pre> with the same text.

Part One · Foundations · Chapter 5

Text Formatting

Emphasis, importance, and the semantics behind bold and italic

The <mark> element (new in HTML5) highlights text "due to its relevance in another context" — the classic case is search-result highlighting. A common default style is black text on a yellow background, but CSS can change it.

For bold text, use <strong> or <b>. The difference is semantic: <strong> conveys importance; <b> simply draws attention without implying importance. A screen reader may speak <strong> text with added emphasis, but not <b> text. For italic, use <em> for stressed emphasis and <i> for stylistic italics (titles, foreign words).

<u> was deprecated in HTML 4 and reintroduced in HTML 5 with a new meaning: an unarticulated but explicitly rendered annotation, such as a misspelled word or a Chinese proper name mark. <abbr title="..."> marks abbreviations. <ins>, <del>, and <s> mark insertions, deletions, and strikethroughs. <sup> and <sub> raise and lower text.

<p>Here is some <mark>highlighted</mark> text.</p>
<p><strong>Bold</strong> and <b>also bold</b>.</p>
<p><em>Stressed italic</em> and <i>stylistic italic</i>.</p>
<p>I like to write <abbr title="Hypertext Markup Language">HTML</abbr>.</p>
<p>Water is H<sub>2</sub>O and E = mc<sup>2</sup>.</p>
<p><del>Old price</del> <ins>New price</ins></p>

Key Ideas

  • <mark> highlights text by relevance, not just colour.
  • <strong> and <em> convey meaning; <b> and <i> are purely stylistic.
  • <u> in HTML5 marks non-textual annotations, not links.
  • <abbr> with title gives the expansion of abbreviations.
  • <ins>, <del>, <s>, <sup>, <sub> cover edit and positional formatting.

Try It Yourself

  1. Write a paragraph that uses all of the elements above.
  2. Open the page in a screen reader and compare <strong> with <b>.
  3. Use <abbr> to define three acronyms.

Anchors and Hyperlinks

The <a> element — the heart of the web

Anchor tags are commonly used to link separate webpages, but they can also link between places in a single document — often within a table of contents — or launch external applications such as a phone dialler or an email client. The href attribute is the destination: an absolute URL, a relative URL, an anchor, or a tel:, mailto:, or javascript: URI.

The target attribute controls where the link opens. _blank opens a new tab or window — but this creates a security risk, because the new page can reach back into the current page via window.opener and potentially redirect users to a phishing site. When using _blank, add rel="noopener" to prevent this attack.

You can link to an anchor within the same page by pointing to an element's id attribute: <a href="#section-id">. You can also use tel: to dial a number, mailto: to open an email client (with optional cc, bcc, subject, and body parameters — all URL-encoded), and javascript: to run code — though the last is strongly discouraged; use a proper event listener and a <button> instead.

<a href="http://example.com/">Link to example.com</a>
<a href="http://example.com/" target="_blank" rel="noopener">Open in new tab</a>
<a href="#Topic1">Jump to the first topic</a>
<a href="tel:+15551234567">Call us</a>
<a href="mailto:example@example.com?subject=Hello&body=Hi!">Send email</a>

Key Ideas

  • The href attribute is the destination; it can be absolute, relative, or an anchor.
  • target="_blank" opens a new tab — always add rel="noopener".
  • tel: dials a number; mailto: opens the email client.
  • Anchor links (#id) jump to elements by their id.
  • Prefer proper event listeners and <button> over javascript: links.

Try It Yourself

  1. Create a table of contents with anchor links to three sections.
  2. Write an email link with a pre-filled subject and body.
  3. Try a tel: link on a desktop and a mobile device.

Lists

Three kinds of lists — ordered, unordered, and description

HTML offers three ways to specify lists. Ordered lists (<ol>) use ordinal sequences; unordered lists (<ul>) use bullets; and description lists (<dl>) use indents to pair names with their values. Every list item inside an ordered or unordered list is a <li>.

Ordered lists support start, value, reversed, and type attributes. start sets the first number; value overrides the number of a specific item (and the numbering continues from that value); reversed counts down; type selects decimal, alphabetic, or Roman numerals.

Nested lists are supported — a sub-list must be a child of an <li>, not a sibling. Description lists use <dt> for the term and <dd> for the description; a single term may have several descriptions, and a single description may serve several terms.

<ol start="3">
  <li>Item</li>
  <li>Another Item</li>
  <li value="7">A Reset Item</li>
</ol>

<ul>
  <li>Item</li>
  <li>Another Item
    <ul>
      <li>Sub-item</li>
    </ul>
  </li>
</ul>

<dl>
  <dt>name 1</dt>
  <dd>value for 1</dd>
  <dt>name 2</dt>
  <dd>value for 2</dd>
</dl>

Key Ideas

  • Use <ol> when order matters, <ul> when it does not.
  • start, value, reversed, and type control ordered-list numbering.
  • Nested lists must live inside the parent <li>.
  • <dl> pairs terms (<dt>) with descriptions (<dd>).

  1. Write an ordered list that starts at 5 and includes a value override.

Tables

Rows, columns, headers, and the semantics of tabular data

The <table> element displays tabular data — text, images, links, even other tables — in a two-dimensional grid of rows and columns. Rows are <tr>; header cells are <th>; data cells are <td>.

Cells can span multiple columns or rows using colspan and rowspan. The defaults are 1; a value of 0 extends the cell to the end of the containing group. You should not design a table where both rows and columns overlap — that is invalid HTML and browsers handle it differently.

For semantic and stylistic structure, tables can contain <caption>, <thead>, <tbody>, and <tfoot>. The <caption> goes first; <thead> and <tfoot> can appear in either order (but <tbody> goes between them logically, regardless of source order). Column groups use <colgroup> and <col>.

The scope attribute on <th> tells assistive technology whether a header applies to a column, row, column group, or row group. Use scope="col" and scope="row" generously.

<table>
  <caption>Table Title</caption>
  <thead>
    <tr>
      <th scope="col">Heading 1</th>
      <th scope="col">Heading 2</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Row 1 Cell 1</td>
      <td>Row 1 Cell 2</td>
    </tr>
    <tr>
      <td colspan="2">A cell spanning two columns</td>
    </tr>
  </tbody>
</table>

Key Ideas

  • Use <th> for headers and <td> for data.
  • colspan and rowspan span cells across columns and rows.
  • <thead>, <tbody>, <tfoot>, and <caption> add semantics.
  • scope="col" and scope="row" help screen readers.
  • Do not design tables where row and column spans overlap.

Comments

Notes to yourself and other developers — invisible to users

HTML comments begin with <!-- and end with -->. They can be single-line, multi-line, or inline within content — the browser will not render anything inside them. They are commonly used to leave notes to yourself, to document tricky markup, or to "comment out" entire blocks of HTML during development.

Comments cannot appear inside another tag. Writing <h1 <!-- x --> attr="..."> produces invalid HTML, because the whole block is treated as a single start tag with junk in it. For compatibility with XML and SGML parsers, the body of a comment should not contain --.

A less-obvious use: commenting out the whitespace between inline elements (like <a> or <button>) prevents the extra space that browsers insert between them. This matters for layout precision.

<!-- A single-line comment -->

<!--
  A multiline comment.
  Nothing in here is rendered.
-->

<!-- Comment out a block of markup -->
<!--
  <div class="hidden-during-development">...</div>
-->

<!-- Eliminating whitespace between inline elements -->
<a href="#">Link</a><!--
--><button>Button</button>

Key Ideas

  • Comments start with <!-- and end with -->.
  • Anything inside a comment is ignored by the browser.
  • Comments cannot live inside another tag.
  • Avoid -- inside comment bodies for XML/SGML compatibility.
  • Use comments to eliminate whitespace between inline elements when precision matters.

Try It Yourself

  1. Comment out a paragraph and confirm it disappears from the rendered page.
  2. Write a single-line and a multi-line comment.

Classes and IDs

Non-unique and unique hooks into your markup

Classes and IDs make referencing elements from scripts and stylesheets easier. The class attribute names one or more classes and can be reused freely across a page. The id attribute names one element uniquely — the same id should never appear twice in a document. Classes are for CSS and repeated behaviours; IDs are for scripting and for anchor links.

In HTML5, an id must be unique, contain no whitespace, and contain at least one character — that is the entire rule. Digits, punctuation, even emoji are legal. However, IDs that are legal in HTML may cause trouble in CSS (which historically disallowed leading digits), JavaScript, and regular expressions. Stick to alphanumerics, hyphens, and underscores.

Duplicate IDs are a common source of bugs. CSS selectors still work — they match every matching element — but document.getElementById returns only the first. The rest of the page may render but scripts will silently misbehave.

<div class="highlight">First item</div>
<span class="highlight">Second item</span>

<div id="main-container">...</div>
<a href="#main-container">Jump to main</a>

<div class="special left menu">Pink?</div>
<!-- CSS: .special.left.menu { color: pink; } -->

Key Ideas

  • Classes are non-unique; IDs are unique within a document.
  • Use classes for styling; use IDs for scripting and anchor links.
  • HTML5 allows almost any non-empty string without whitespace as an ID.
  • Duplicate IDs do not break CSS but break getElementById.
  • Prefer class selectors over ID selectors in CSS.

Try It Yourself

  1. Give three elements the same class and style them together.

  3. Link to a section using an ID and an anchor.

Data Attributes

Store your own data on any element — without inventing attributes

HTML5 data-* attributes provide a standard way to store data on HTML elements. The name after data- is up to you; the value is a string. You can read and modify these attributes from JavaScript via element.dataset or via getAttribute/setAttribute.

Before HTML5, developers invented non-standard attributes to carry data — usually in the value attribute of non-form elements, or in arbitrary names. Browsers ignored them when rendering, which made them useful. But they were invalid HTML and could confuse validators and future versions of the language. data-* gives this practice a proper home.

Data attributes work in every modern browser. In older browsers, the attributes themselves are preserved but the convenience dataset API is not — use getAttribute("data-foo") instead.

<div data-submitted="yes" class="user_profile">
  ... some content ...
</div>

<script>
  var el = document.querySelector(".user_profile");
  console.log(el.dataset.submitted);          // "yes"
  console.log(el.getAttribute("data-submitted")); // "yes"
</script>

Key Ideas

  • data-* attributes hold arbitrary custom data on any element.
  • Read them with element.dataset or getAttribute.
  • Older browsers preserve the attributes but not the dataset API.
  • Use data-* instead of inventing non-standard attribute names.

Linking Resources

The <link> element — stylesheets, favicons, and performance hints

The <link> element links external resources into the current document. By far its most common use is stylesheets — <link rel="stylesheet" href="path/to.css"> — but it also declares favicons, alternate stylesheets, RSS feeds, prev/next relationships, and performance hints.

Performance hints include dns-prefetch (resolve DNS for a URL ahead of time), preconnect (DNS + TCP + TLS), prefetch (download a resource the user is likely to need), and prerender (fetch and render a page in the background). dns-prefetch only resolves the domain; prefetch downloads the resource itself.

The media attribute lets you load stylesheets conditionally — for example, media="print" loads the sheet only when printing. The integrity attribute lets you specify a base64-encoded hash of the linked resource, so the browser can verify that it has not been tampered with — essential for CDN-hosted assets.

<link rel="stylesheet" href="path/to.css">
<link rel="stylesheet" href="print.css" media="print">

<link rel="icon" type="image/png" href="/favicon.png">

<link rel="dns-prefetch" href="//cdn.example.com">
<link rel="preconnect" href="https://cdn.example.com">
<link rel="prefetch" href="/next-page.html">

<link rel="stylesheet" href="https://cdn.example.com/lib.css"
      integrity="sha384-..." crossorigin="anonymous">

Key Ideas

  • <link> is most often used for stylesheets and favicons.
  • media loads a stylesheet only under certain conditions.
  • Performance hints: dns-prefetch, preconnect, prefetch, prerender.
  • integrity verifies CDN-hosted resources with a hash.
  • Use crossorigin with integrity when fetching from another origin.

  1. Add a favicon link to a page.

Part Three · Media and Forms · Chapter 13

Include JavaScript Code in HTML

Scripts inline, external, async, deferred — and noscript

The <script> element embeds or links JavaScript. Standard practice is to place script tags just before the closing </body> tag: loading scripts last lets the visual content render quickly, and discourages the script from trying to touch elements that have not yet loaded.

Two attributes change when scripts execute. async downloads the script in parallel and runs it as soon as it is ready, interrupting HTML parsing. defer also downloads in parallel but waits until HTML parsing is complete before executing, and preserves the original order of scripts. Use defer for most application code; use async for independent third-party scripts like analytics.

The <noscript> element shows its content when scripts are disabled or unsupported. It can appear in the <head> or <body>. Always give users some graceful message when your page relies on JavaScript.

<!-- Synchronous, before the closing body tag -->
<script src="app.js"></script>

<!-- Asynchronous -->
<script src="analytics.js" async></script>

<!-- Deferred -->
<script src="app.js" defer></script>

<!-- Inline -->
<script>
  document.write("Hello, world!");
</script>

<noscript>This browser does not support JavaScript.</noscript>

Key Ideas

  • Place script tags just before </body> for fast rendering.
  • async runs as soon as downloaded; order not guaranteed.
  • defer runs after HTML parsing; order guaranteed.
  • <noscript> shows content when JavaScript is off.
  • Prefer external files for caching and maintainability.

Try It Yourself

  1. Load a script with async, then with defer, and observe the timing.
  2. Disable JavaScript in your browser and confirm the <noscript> text appears.
  3. Add an inline script that logs the page title to the console.

Part Three · Media and Forms · Chapter 14

Using HTML with CSS

External, internal, and inline — the three ways to attach styles

CSS provides styles to HTML elements. There are three ways to attach CSS to a document. External stylesheets use a <link> tag in the document's <head> and are the recommended approach for real projects. Internal stylesheets use a <style> tag inside <head> and are useful for single-page demos. Inline styles use the style attribute on individual elements and are strongly discouraged, because they mix content with presentation.

Multiple stylesheets can be loaded. When they conflict, later declarations win — but CSS specificity and source order also matter, so the general rule is only a starting point. A widely-used CDN stylesheet (like Bootstrap) can be dropped in with a single <link>, complete with integrity and crossorigin attributes for security.

<!-- External stylesheet (preferred) -->
<head>
  <link rel="stylesheet" href="stylesheet.css">
</head>

<!-- Internal stylesheet -->
<head>
  <style>
    body { background-color: gray; }
    p    { background-color: blue; }
  </style>
</head>

<!-- Inline style (avoid) -->
<span style="color:red">This text will appear in red.</span>

Key Ideas

  • External stylesheets are the recommended approach.
  • Internal stylesheets live in a <style> block in <head>.
  • Inline styles mix content with presentation — avoid them.
  • When multiple stylesheets conflict, later declarations usually win.
  • Use integrity and crossorigin for CDN-hosted CSS.

Try It Yourself

  1. Add an external, an internal, and an inline style to the same page.
  2. Load two stylesheets that both set body colour and observe which wins.
  3. Link Bootstrap from a CDN with an integrity hash.

Images

The <img> element and the art of writing good alt text

The <img> tag inserts an image into a page. Its two essential attributes are src — the URL of the image — and alt — the alternative text describing the image. Images are technically not embedded in HTML; the <img> tag creates a holding space for the referenced image. Images can also be embedded directly via a base64 data: URL.

Alt text is used by screen readers and search engines, so writing good alt text matters. The rule of thumb: the page should still make sense if you replace every image with its alt attribute. Decorative images should have an empty alt=""; images that convey meaning should have descriptive text. A missing alt attribute is not the same as an empty one — the former tells screen readers the image matters but has no textual equivalent.

For responsive images, use srcset with sizes to give the browser a choice of resolutions, or the <picture> element with <source> children for art direction. The src attribute is always the fallback.

<img src="images/hello.png" alt="Hello World">

<img src="avatar.png" alt=""> An anonymous user wrote:

Input Control Elements

Every type of input, from text to datetime

Input tags are HTML elements designed to take a specific form of input from users. Different type values regulate the format of data and provide security for sensitive fields. The default type is text: a single-line field for arbitrary strings. Setting size controls the visual width of a text field, not the maximum length — for that, use maxlength.

Checkboxes and radio buttons are written as <input type="checkbox"> and <input type="radio">. A checkbox is binary and independent; radio buttons form a group identified by a shared name, and only one can be selected. Always wrap each in a <label> for accessibility.

HTML5 added input validation: required, minlength/maxlength, min/max, pattern, and accept. Validation is enforced when submitting a form and can be bypassed — it never replaces server-side validation. New types like email, url, tel, date, color, number, range, search, time, and week provide specialised controls and automatic validation where supported.

<input type="email" name="email" required>

<input type="file" accept="image/*">

Forms

Collecting input and submitting it — GET, POST, and files

Forms group inputs and submit their data to a server. The action attribute names the target URL; method selects GET (data appended to the URL as a query string) or POST (data sent in the request body). If action is omitted, the form submits to the current page.

To upload files, set enctype="multipart/form-data" — otherwise the file input will submit only the filename. Each control that should submit data needs a name attribute; without it, the field is skipped.

Use <fieldset> to group related inputs and <legend> to label the group. The target attribute controls where the response opens; novalidate disables client-side validation. On the submit button, formnovalidate disables validation only for that button — perfect for a "save draft" button alongside a "publish" button.

<form action="submit.php" method="post"
      enctype="multipart/form-data"
      accept-charset="UTF-8">
  <fieldset>
    <legend>Contact details</legend>
    <label for="name">Name:</label>
    <input type="text" id="name" name="name" required>

    <label for="photo">Photo:</label>
    <input type="file" id="photo" name="photo" accept="image/*">
  </fieldset>

  <button type="submit">Publish</button>
  <button type="submit" formnovalidate>Save draft</button>
</form>

Key Ideas

  • action is the URL; method is GET or POST.
  • Use enctype="multipart/form-data" for file uploads.
  • Every field needs a name to submit its value.
  • <fieldset> and <legend> group and label related inputs.
  • formnovalidate on a submit button skips validation for that button only.

Div Element

The last-resort container — powerful and dangerous

The <div> element groups other elements and separates one block of content from another. It has no inherent meaning — W3C calls it "an element of last resort". Use <article>, <section>, <nav>, or <fieldset> where those fit better; reach for <div> only when no semantic element is appropriate.

A <div> is a block-level element, so it occupies the full width of the page (unless CSS overrides this). Nesting <div>s is common, but deep nesting is an anti-pattern: aim for shallow hierarchies. W3C advises not nesting deeper than six levels.

<div class="outer-div">
  <div class="inner-div">
    <p>This is a paragraph.</p>
  </div>
  <div class="inner-div">
    <p>This is another paragraph.</p>
  </div>
</div>

Key Ideas

  • <div> is a generic container with no semantic meaning.
  • Prefer semantic elements (<article>, <section>, <nav>) when applicable.
  • Divs are block-level by default; CSS can change that.
  • Avoid deep nesting — aim for six levels or fewer.

Sectioning Elements

nav, article, main, header, footer, section — the semantics of a page

HTML5 introduced semantic sectioning elements so that a page's structure is expressed in markup, not just in visual layout. <nav> holds primary navigation; <article> holds self-contained content that could stand alone in an RSS feed; <main> holds the unique main content of a page (only once per page); <header> and <footer> hold introductory and closing content; <section> groups thematically related content that has a heading.

Rules worth remembering: <main> must not be inside <article>, <aside>, <footer>, <header>, or <nav>. <main> is unique to a page — repeating it across pages is a mistake. When nesting <article> elements, the inner articles should be related to the outer one (e.g. comments on a blog post). Use <section> with a heading, not as a generic container — for that, use <div>.

Adding ARIA role attributes (role="navigation", role="main", role="article") is recommended for older user agents that predate HTML5.

<body>

  • <section> needs a heading; use <div> for purely presentational containers.

A list of links — wrapped in a <nav>

Label Element

Give every input a name — and make the name clickable

The <label> element attaches a readable label to a form control. It can wrap the control, or point at it with a for attribute whose value matches the control's id. Either way, clicking the label focuses or activates the associated control — a big usability and accessibility win, especially for checkbox and radio buttons.

Never put more than one control inside a single <label>. If you need to associate a control that lives elsewhere in the document, use the for attribute — that is also how to attach a label to a form defined outside the current subtree. In HTML5, the form attribute lets a control associate itself with a form even when it lives outside the form's markup.

<!-- Wrapping -->
<label>
  <input type="checkbox" name="cats">
  I like cats!
</label>

<!-- Referencing -->
<input id="cats" type="checkbox" name="cats">
<label for="cats">I like cats!</label>

<!-- Association across the document -->
<form id="login">
  <input id="username" type="text" name="username">
  <input type="submit" value="Log in">
</form>
<label for="username" form="login">Username:</label>

Key Ideas

  • <label> gives a form control a readable, clickable name.
  • Wrap the control, or use for="id" to link the label and control.
  • Never put more than one control in a single label.
  • form="id" associates a control with a form elsewhere in the document.

Output Element

A live region for calculated results

The <output> element represents the result of a calculation or user action. It is a form-associated element: it can be associated with a form, and it accepts for and form attributes to declare which controls it is a result for and which form it belongs to. Its primary purpose is to give assistive technology a live region that announces calculated values.

<output> needs JavaScript to actually display live values; the element itself does not compute anything. Even though inputs may have type="number", their .value is a string — convert with parseInt, parseFloat, or Number().

Void Elements

Elements with no closing tag and no content

Most HTML elements require an opening tag, a closing tag, and content. Void elements are the exception: they have no content and no closing tag. HTML4 had thirteen of them — area, base, br, col, hr, img, input, link, meta, param. HTML5 adds command (obsolete), keygen (deprecated), source, and track, and formally includes embed and wbr.

In HTML5, a void element is written as just its opening tag: <br>, <hr>, <input>. The self-closing slash (<br />) is XHTML syntax; it is tolerated in HTML5 but not necessary. If you do use it, put a space before the slash: <br />, not <br/>.

<img src="logo.png" alt="Logo">
<br>
<hr>
<input type="number" placeholder="Enter a number">
<meta charset="UTF-8">
<link rel="stylesheet" href="styles.css">

Key Ideas

  • Void elements have no content and no closing tag.
  • Common void elements: img, br, hr, input, meta, link.
  • The self-closing slash is XHTML syntax; optional in HTML5.
  • Never add a closing tag to a void element.

Media Elements

Audio and video without plugins

HTML5 introduced <audio> and <video>, so pages can embed media without Flash or other plugins. Both accept a src attribute, or one or more <source> elements from which the browser chooses the format it supports best. The <track> element attaches subtitles or captions.

Attributes common to both elements: controls (show playback UI), autoplay (start playing when ready), loop (repeat), muted (no sound — required by most browsers if autoplay is used), and poster (an image shown until video loads). Width and height are in pixels.

For decorative video backgrounds, use autoplay muted loop and provide multiple sources so the browser picks a codec it can decode. Always include fallback text inside the element for older browsers.

<video width="480" height="270" controls poster="poster.jpg">

  <source src="video.mp4" type="video/mp4">
  Your browser doesn't support HTML5 video.
</video>

  <source src="audio.ogg" type="audio/ogg">

  <source src="bg.webm" type="video/webm">
  <source src="bg.mp4"  type="video/mp4">
</video>

The <progress> element (new in HTML5) represents the progress of a task. The two key attributes are value (how much has been done) and max (the total). Omitting value shows an indeterminate progress bar — useful when you have no way to estimate.

Styling progress bars is notoriously awkward. Chrome, Safari, and Opera use -webkit-appearance; Firefox uses -moz-appearance. To style them, reset the appearance first and then apply background and colour. Internet Explorer 10+ supports the element but ignores background-color — use color instead.

Selection Menu Controls

The <select> element generates a drop-down menu of <option> elements. The size attribute controls how many options are visible: 0 or 1 shows the standard drop-down; a value greater than 1 converts it to a scrollable list. The multiple attribute allows more than one choice and also turns the drop-down into a list box.

Each <option> has a value (what gets sent with the form) and a label (what the user sees). If the value is omitted, the option's text is used. <optgroup> groups related options under a label. A disabled <optgroup> disables all its children. The <datalist> element provides autocomplete suggestions for an input — the user can still type anything they like.

IFrames

A window into another page — and how to sandbox it

An inline frame (<iframe>) embeds another HTML page inside the current page. The src attribute is the page to embed; width and height set its dimensions (in CSS pixels; percentages are no longer allowed in HTML5). The name attribute lets a link or form target the frame.

The sandbox attribute is critical when embedding untrusted content. With an empty value, it disables scripts, forms, plugins, and popups, and treats the content as coming from a unique origin. You can relax individual restrictions by adding values like allow-scripts, allow-forms, and allow-same-origin. Sandboxing is not a replacement for sanitising input — it is one layer in a defence-in-depth strategy.

The srcdoc attribute embeds an entire HTML document as a string, rather than pointing at a URL. If both src and srcdoc are present, srcdoc wins. Use <iframe> sparingly — search engines may not crawl its content, and it has accessibility implications.

<iframe src="https://example.com/page" width="800" height="600"></iframe>

<iframe sandbox src="https://example.com/untrusted"></iframe>

<iframe sandbox="allow-scripts allow-forms"
        src="https://example.com/interactive"></iframe>

<iframe srcdoc="<p>Hello, embedded world!</p>"></iframe>

<iframe src="page.html" name="myFrame"></iframe>
<a href="other.html" target="myFrame">Change the frame</a>

Key Ideas

  • <iframe> embeds another page inside the current one.
  • sandbox disables scripts, forms, and plugins by default.
  • Add allow-scripts, allow-forms, allow-same-origin selectively.
  • srcdoc embeds inline HTML and takes precedence over src.
  • Use name + target to control the frame from outside.

Content Languages

Declaring the language of a page and its parts

The lang attribute declares the human language of content. At the document level, put it on <html>: <html lang="en">. This helps screen readers choose the right pronunciation, search engines index language, and browser spell-checkers behave.

You can override the language on any element — for example, an English page with a German quotation uses <span lang="de">. Use BCP 47 language tags (en, en-US, de, fr-CA), not invented codes.

Regional URLs and language-specific content types use hreflang on links. The dir attribute (also global) selects left-to-right (ltr) or right-to-left (rtl) — crucial for Arabic, Hebrew, and Persian.

    <a href="https://example.fr/" hreflang="fr">Version française</a>
  </body>
</html>

  • lang declares the language of the content; put it on <html>.

SVG

Scalable Vector Graphics, written directly into HTML

SVG — Scalable Vector Graphics — defines vector graphics for the web. The <svg> element is a container for SVG graphics, which can be styled and manipulated with CSS and JavaScript when written inline. SVG paths, circles, rectangles, and text are all described by XML elements, and the graphics scale infinitely without loss of quality.

You can embed SVG three ways. Inline: paste the SVG markup directly into HTML — this lets you style it with CSS and script it with JavaScript. External with <img>: the simplest option, but the SVG cannot be styled or scripted. External with <object>: imports the SVG into the document, so it can be styled and scripted.

External SVGs can also be used as CSS background-image — either by URL or as an inline data: URL.

<svg viewBox="0 0 100 100" class="attention">
  <path d="M 50 5 L 95 95 L 5 95 Z" fill="red" />
</svg>

<img src="attention.svg" width="50" height="50" alt="Alert">

<object type="image/svg+xml" data="attention.svg"
        width="50" height="50"></object>

<div class="attention"></div>
<style>
  .attention { background: url(attention.svg); }
</style>

Key Ideas

  • SVG is vector graphics: infinitely scalable, scriptable, styleable.
  • Inline SVG can be styled and scripted with CSS and JS.
  • <img> embeds an SVG but cannot style or script it.
  • <object> imports the SVG so it can be styled and scripted.
  • SVG can be used as a CSS background image.

Canvas

Pixel-based drawing with JavaScript

The <canvas> element (new in HTML5) provides a drawing surface that JavaScript can use for shapes, graphs, image manipulation, and games. By default, a canvas is 300×150 CSS pixels. Unlike SVG, canvas graphics are raster: you cannot select, style, or inspect them after they are drawn — you can only re-draw them.

To draw, first get the canvas element's 2D drawing context with canvas.getContext("2d"). Then use its methods — fillStyle, fillRect, strokeStyle, strokeRect, beginPath, arc, fill, fillText, and so on. Each drawing operation paints on top of the previous ones; there is no automatic clearing.

<canvas id="myCanvas" width="300" height="150">
  Your browser does not support canvas.
</canvas>

<script>
  var canvas = document.getElementById("myCanvas");
  var ctx = canvas.getContext("2d");

  ctx.fillStyle = "red";
  ctx.fillRect(0, 0, 100, 100);

  ctx.fillStyle = "green";
  ctx.fillRect(25, 25, 50, 50);

  ctx.fillStyle = "black";
  ctx.fillText("Hello, canvas!", 24, 130);
</script>

Key Ideas

  • <canvas> is a raster drawing surface controlled by JavaScript.
  • getContext("2d") returns the drawing context.
  • Canvas graphics cannot be styled or selected after drawing.
  • The default canvas size is 300×150 CSS pixels.
  • Always provide fallback content inside the tag.

  1. Draw a red rectangle and a green rectangle inside it.
  2. Write "Hello" with fillText.

Meta Information

The invisible head — SEO, social sharing, and device control

<meta> tags describe the document: author, description, keywords, generator, character encoding, viewport, robots, and social media metadata. <meta charset="UTF-8"> declares the character encoding and should be the very first meta tag. <meta name="viewport" content="width=device-width, initial-scale=1"> makes pages render correctly on mobile devices.

The description meta tag becomes the snippet under your page title in search-engine results. The robots meta tag controls whether search engines may index a page and follow its links — values include noindex, nofollow, none, and noarchive. Use them sparingly; the default is to index and follow.

Open Graph (og:*) and Twitter Card (twitter:*) meta tags control how links to your page look when shared on social media — the card image, title, description, and type. These tags are widely used and affect CTR from social networks.

Two related redirect techniques — <meta http-equiv="refresh" content="5"> for a timed refresh and <meta http-equiv="refresh" content="5;url=..."> for a redirect — are discouraged because they hurt user experience. Use HTTP redirects and JavaScript instead.

<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="description" content="Page description for search engines.">
<meta name="author" content="Your Name">
<meta name="robots" content="noindex, nofollow">

<!-- Open Graph / Facebook -->
<meta property="og:title" content="Content Title">
<meta property="og:image" content="https://example.com/image.jpg">
<meta property="og:description" content="Description Here">
<meta property="og:type" content="website">

<!-- Twitter -->
<meta name="twitter:card" content="summary">
<meta name="twitter:title" content="Content Title">
<meta name="twitter:description" content="Description under 200 characters">
<meta name="twitter:image" content="https://example.com/image.jpg">

Key Ideas

  • <meta charset> declares character encoding; UTF-8 is the standard.
  • <meta name="viewport"> makes pages responsive on mobile.
  • description becomes the search-engine snippet; robots controls indexing.
  • Open Graph and Twitter Card meta tags shape link previews on social media.
  • Avoid meta refresh redirects; use HTTP or JavaScript.

Try It Yourself

  1. Add a description, author, and viewport meta tag to a page.
  2. Add Open Graph tags and preview a link to your page in a social app.
  3. Try meta name="robots" content="noindex" and verify it appears in the page source.

Marking up computer code

pre and code — for text that must keep its shape

When the formatting — whitespace, newlines, indentation — of a block of code matters, use <pre> together with <code>. The <pre> element preserves whitespace; the <code> element marks up code semantically. Inside the block you still have to escape the HTML-significant characters <, >, and &.

For inline code — the name of an element, a property, or a short expression — just wrap it in <code> without <pre>. It renders in a monospace font by default, though you can change that with CSS.

<pre><code>
x = 42
if x == 42:
    print("x is 42")
</code></pre>

<pre><code>
&lt;p&gt;This is a paragraph.&lt;/p&gt;
</code></pre>

<p>The <code>a</code> element creates a hyperlink.</p>

Key Ideas

  • <pre> preserves whitespace; <code> marks code semantically.
  • Use <pre><code> together for code blocks.
  • Escape <, >, and & inside code blocks.
  • Use <code> alone for inline code.

Try It Yourself

  1. Write a code block with Python-like indentation.
  2. Show a fragment of HTML as text, with all angle brackets escaped.
  3. Use inline <code> for an element name.

Part Six · Graphics and Metadata · Chapter 35

Marking-up Quotes

q and blockquote — for quote marks the browser adds for you

Use <q> for quotes that sit inside a sentence, and <blockquote> for quotes that occupy a whole block. In HTML5, you must not add quotation marks around <q> text — the browser inserts them. The same applies to <blockquote>: the browser may style it, but you should not add visual quotes yourself.

Both elements accept a cite attribute pointing at the source URL. Browsers typically do not display it, so if the source is relevant to readers, add a visible hyperlink. In HTML5, the citation may live inside the <blockquote> — but only inside a <cite> or <footer>.

<p>She wrote <q>The answer is 42.</q> and everyone agreed.</p>

<blockquote cite="http://example.com/blog/hello-world">
  <p>The answer is 42.</p>
  <footer>
    <cite>
      <a href="http://example.com/blog/hello-world">Hello World</a>
    </cite>
  </footer>
</blockquote>

Key Ideas

  • <q> is inline; <blockquote> is block-level.
  • Do not add quotation marks — the browser inserts them.
  • cite on either element references the source URL.
  • Citations inside a blockquote must live in <cite> or <footer> (HTML5).
  • If the source matters, add a visible link too.

Try It Yourself

  1. Write a sentence with an inline <q> and check that the quotes appear automatically.
  2. Wrap a paragraph in <blockquote> and add a citation.
  3. Add the cite attribute to both.

Tabindex

Control the order in which the Tab key visits elements

tabindex is a global attribute that makes an element focusable. With tabindex="0", the element becomes focusable and joins the normal tab order at its document position. With tabindex="-1", the element is focusable programmatically but skipped by Tab. Positive values override the natural order entirely — and are strongly discouraged.

Before adding tabindex to a non-interactive element, ask whether a native interactive element would be better: <button>, <a href>, <input>. Native elements are keyboard-accessible and screen-reader-friendly without extra work. Positive tabindex values disrupt the natural order and confuse screen reader users.

<div tabindex="0">Focusable div (avoid)</div>

<button tabindex="-1">Focusable by JS, not by Tab</button>

<!-- Better than tabindex="0" on a div -->
<button>Native button</button>

Key Ideas

  • tabindex="0" makes an element focusable in document order.
  • tabindex="-1" makes an element focusable only via JavaScript.
  • Positive tabindex values are not recommended.
  • Prefer native interactive elements over tabindex hacks.

Try It Yourself

  1. Add tabindex="0" to a <div> and Tab to it.
  2. Add tabindex="-1" to a button and use JS .focus() on it.
  3. Replace a focusable div with a real <button>.

Global Attributes

The attributes every HTML element accepts

Global attributes work on any HTML element. class names one or more classes; id names the element uniquely. contenteditable makes the content editable; dir sets text direction; hidden hides the element; lang declares the language; style applies inline CSS; tabindex controls focus; title adds a tooltip; spellcheck toggles spell-checking; draggable makes the element draggable; translate controls translation by user agents.

contenteditable is inherited — children become editable unless they explicitly set contenteditable="false". But an uneditable child inside an editable parent still inherits the text cursor, which can confuse users.

<p contenteditable>
  This is an editable paragraph.
  <span contenteditable="false">But this part is not editable.</span>
</p>

<div class="card" id="card-1" title="Hover me">
  Card content
</div>

Key Ideas

  • Global attributes apply to every HTML element.
  • contenteditable makes content editable in the browser.
  • hidden hides an element without removing it from the DOM.
  • lang and dir affect reading direction and pronunciation.
  • title adds tooltip text; use it judiciously.

Try It Yourself

  1. Add contenteditable to a paragraph and edit it.
  2. Use hidden to hide an element and show it via JavaScript.
  3. Add title to an image and hover it.

Part Seven · Accessibility and Legacy · Chapter 38

HTML 5 Cache

Offline access with an appcache manifest — a legacy technique

The HTML5 Application Cache (appcache) allowed a web app to specify which files should be cached for offline use. It worked by pointing <html manifest="index.appcache"> at a manifest file that listed resources under a CACHE MANIFEST header. Browsers then stored the files locally and served them when the network was unavailable.

AppCache was deprecated and removed from browsers in favour of Service Workers, which provide better control, better caching strategies, and no odd update behaviour. If you are reading this book to learn modern techniques, use a Service Worker instead. If you maintain legacy code that still uses AppCache, this is how it worked.

<!DOCTYPE html>
<html manifest="index.appcache">
  <body>
    <p>Content</p>
  </body>
</html>

<!-- index.appcache -->
CACHE MANIFEST
index.html
styles.css
script.js

Key Ideas

  • AppCache declared offline-cacheable files via a manifest file.
  • The manifest was referenced with the manifest attribute on <html>.
  • AppCache is deprecated and removed from browsers.
  • Service Workers are the modern replacement.

Try It Yourself

  1. Read the deprecation notice for AppCache in your browser's documentation.
  2. Write a minimal Service Worker that caches the current page.
  3. Load the page offline and confirm the Service Worker serves it.

HTML Event Attributes

Inline handlers — convenient, tempting, and mostly not recommended

HTML event attributes run JavaScript in response to user actions: onclick, oninput, onsubmit, onkeydown, and dozens more. They are easy to write and hard to maintain. Inline handlers mix markup with behaviour, are hard to test, and cannot be reused or removed as easily as listeners added via addEventListener.

Form events (onblur, onchange, onfocus, oninput, oninvalid, onreset, onsearch, onselect, onsubmit) fire as the user interacts with form controls. Keyboard events (onkeydown, onkeypress, onkeyup) fire when keys are pressed and released. onclick fires on click; onload fires when the page or an image has loaded.

For modern code, prefer addEventListener — it separates concerns, works with any number of listeners, and does not pollute the global scope with function names.

<!-- Inline handler (works, but discouraged) -->
<button onclick="alert('Hello!')">Say Hello</button>

<!-- Better: attach a listener -->
<button id="greet">Say Hello</button>
<script>
  document.getElementById("greet").addEventListener("click", function () {
    alert("Hello!");
  });
</script>

<!-- Form event example -->
<form onsubmit="return validateForm()">
  <input type="text" name="name" required>
  <input type="submit">
</form>

Key Ideas

  • Event attributes run JavaScript in response to user actions.
  • Common events: click, input, change, submit, keydown.
  • Inline handlers mix markup with behaviour and are hard to maintain.
  • Prefer addEventListener in modern code.

Try It Yourself

  1. Attach a click handler to a button inline.
  2. Attach the same handler with addEventListener.
  3. Add a submit handler that logs the form values.

Character Entities

Writing symbols that would otherwise break the markup

Some characters are reserved in HTML and cannot be written literally — most importantly <, >, and &. Some characters are not available on a standard keyboard, or are easily confused with other characters. Character entities solve both problems: an entity begins with &, ends with ;, and is either a named entity (&copy;) or a numeric one (&#169;).

The most important entities are &lt; for <, &gt; for >, &amp; for &, &nbsp; for a non-breaking space, and &quot; for a double quote. A full list is maintained by the W3C.

Use numeric entities when the character you want has no memorable name, and named entities when they exist — they are more readable. Non-breaking spaces are the exception: they are invisible and can hurt layout if used carelessly.

<p>5 &lt; 10 &amp;&amp; 10 &gt; 5</p>
<p>&copy; 2024 Stack Exchange Inc.</p>
<p>100&nbsp;km</p>
<p>A non-breaking space between 100 and km keeps them on one line.</p>

<input type="text" placeholder="&#128269; Search">

Key Ideas

  • Character entities start with & and end with ;.
  • Named entities (&copy;) and numeric entities (&#169;) both work.
  • Escape <, >, and & to avoid breaking markup.
  • &nbsp; is a non-breaking space.
  • Prefer named entities — they are more readable.

Try It Yourself

  1. Display the text <p> literally using entities.
  2. Show the copyright symbol with &copy;.
  3. Use &nbsp; to keep a number and a unit on one line.

ARIA

Roles and attributes that describe intent to assistive technology

ARIA — Accessible Rich Internet Applications — is a set of roles and attributes that describe the purpose and state of UI elements to assistive technologies. The role attribute assigns a role; aria-* attributes describe states and relationships. ARIA is essential for custom widgets (sliders, tabs, custom menus) that have no native HTML equivalent — and unnecessary on elements that already have semantic HTML.

Never add a role that contradicts the element's native semantics. <button role="button"> is redundant; <div role="button"> is a common workaround but requires extra JavaScript for keyboard handling. Prefer semantic HTML wherever possible.

Some of the most useful roles: alert (urgent, live status message), alertdialog, application, article, banner, button, checkbox, dialog, form, grid, group, heading, img, link, list, listbox, listitem, main, menu, menubar, menuitem, navigation, progressbar, radio, region, search, slider, status, tab, tablist, textbox, timer, toolbar, tooltip, tree, treeitem. Live regions (aria-live, aria-atomic, aria-busy) announce dynamic changes to screen-reader users.

<div role="alert" aria-live="assertive">
  Your session will expire in 60 seconds.
</div>

<div role="alertdialog">
  <h1>Warning</h1>
  <div role="alert">Your session will expire.</div>
</div>

<div role="group">
  <button role="button">Previous</button>
  <button role="button">Next</button>
</div>

<ul role="list">
  <li role="listitem">One</li>
  <li role="listitem">Two</li>
  <li role="listitem">Three</li>
</ul>

Key Ideas

  • ARIA describes roles and states to assistive technology.
  • Use it for custom widgets that have no native HTML equivalent.
  • Do not duplicate native semantics with redundant roles.
  • Live regions (aria-live) announce dynamic content changes.
  • Prefer semantic HTML; ARIA is a supplement, not a replacement.

Try It Yourself

  1. Add role="alert" to a notification element and trigger it.
  2. Inspect a custom slider with a screen reader and observe its ARIA role.
  3. Replace a <div role="button"> with a real <button>.

Glossary of Useful Terms

The vocabulary of professional HTML5

Key Terms

Alt text
Alternative text for an image, used by screen readers and search engines and shown when the image fails to load.
ARIA
Accessible Rich Internet Applications — attributes and roles that describe UI elements to assistive technology.
Attribute
A name/value pair attached to an element's opening tag that configures the element.
Block-level element
An element that occupies the full width available and starts a new line in the visual layout.
Character entity
A text sequence such as &lt; that represents a single character in HTML.
Class
A non-unique attribute that names one or more classes for styling and scripting.
Data attribute
A data-* attribute that stores custom data on an element, readable via dataset.
Doctype
The <!DOCTYPE html> declaration that must come first in an HTML document.
DOM
The Document Object Model — the in-memory tree of elements that JavaScript interacts with.
Element
An HTML construct consisting of a start tag, optional content, and an end tag (or a single void tag).
Form-associated element
An element that can belong to a <form>, such as input or output.
Global attribute
An attribute that applies to any HTML element, such as class, id, lang, or hidden.
ID
A unique identifier for one element in a document, targetable by CSS, JavaScript, and anchor links.
Inline element
An element that occupies only as much width as its content requires and does not start a new line.
MIME type
A string such as video/mp4 or text/css declaring the media type of a resource.
Open Graph
A metadata vocabulary (the og:* tags) that describes how a page appears when shared on social media.
Polyfill
JavaScript that adds modern features to older browsers that lack native support.
Screen reader
Assistive software that reads on-screen content aloud, using semantics and ARIA for structure.
Semantic HTML
Using elements whose names describe their purpose, rather than generic containers like <div>.
Shadow DOM
A scoped subtree of DOM nodes that isolates styles and markup — the basis of Web Components.
SVG
Scalable Vector Graphics — an XML format for describing vector images, embeddable in HTML.
Tab order
The order in which elements receive focus when the Tab key is pressed.
Tag
The syntactic unit of an element — <p> is a start tag, </p> is an end tag.
UTF-8
A variable-width character encoding that covers the whole Unicode range — the standard for web pages.
Void element
An element that has no content and no closing tag, such as <img>, <br>, or <input>.
W3C
The World Wide Web Consortium — one of the standards bodies behind HTML and related specs.
Web Component
A reusable custom element built from Custom Elements, Shadow DOM, and HTML Templates.
WHATWG
The Web Hypertext Application Technology Working Group, which maintains the HTML Living Standard.
